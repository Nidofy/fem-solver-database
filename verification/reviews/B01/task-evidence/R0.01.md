## Verified problem anchors for B01 (from actual source, not old reports)

1. `include/sdb/results/results.hpp` `ResultPublisher::publish()` calls
   `cpu.forces(state)` **unconditionally, before** any `OutputScheduler::due()`
   check. `examples/sdb_run.cpp` calls `snapshot()` (which calls `publish()`)
   after **every** increment. On non-output increments this is a full element
   loop + assembly that is then discarded because no field is due and
   `ResultWriter::write()` skips empty frames. This is the R1.01 target.
2. Existing `ResultWriter::write()` already skips frames with no fields — the
   "empty frames written to disk" failure mode does NOT exist at this HEAD.
3. Publication time layer: `publish()` re-evaluates constitutive state at the
   *current* displacement so published U/V/A/S/E/RF/ALL* belong to one coherent
   physical time; velocity is reconstructed to full time `v(t) = v(t-dt/2) +
   dt/2 * a(t)`. R1.02 must lock this contract with tests (read-only w.r.t.
   trajectory, consistent across step/dt changes and restart).
