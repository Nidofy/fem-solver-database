# R0.04 — Cold / steady-state / IO benchmark baseline (and R1.01 A/B)

Machine: Windows 10.0.26200 x64, 16 logical cores, MinGW-w64 g++ 15.2.0
Release, OMP via libgomp 4.5. Date: 2026-10-24.

## What was measured

`benchmarks/lifecycle_benchmark.cpp` was extended **additively** (old JSON keys
keep their meaning; new keys added; generated model now runs 21 increments
with output frequency 10 so a run covers both a non-due and a due pure-U
publication):

- cold: `compile_ms` (IR→mesh→plan), `kernel_ms` (first advance)
- steady: `steady_kernel_ms` / `steady_kernel_per_increment_ms`
  (increments 2–9, away from first-touch)
- publication: `nondue_snapshot_ms` (snapshot at non-due increment),
  `snapshot_ms` (due pure-U frame)
- IO: `native_write_ms`, `reader_scan_query_ms`, `restart_write_ms`,
  `restart_restore_ms`
- introspection: `force_evaluations`, `peak_process_bytes` (budget-enforced)

## Conditions

- Same binary flags/Release build; serial = `OMP_NUM_THREADS=1`, omp4 = 4.
- Sizes: 200 000 nodes × 3 runs each (median reported) and 1 000 000 nodes ×
  1 run. 4096 MiB memory budget.
- **A/B for R1.01**: `lazy` = current dev/glm-b01 tree; `eager` = identical
  tree with only `include/sdb/results/results.hpp` reverted to pre-R1.01
  (commit fcc3c80~1), built separately (`build-b01-eager`). Identical
  benchmark binary source in both.
- Raw JSONL: `benchmarks/lifecycle_*.jsonl`; medians + deltas:
  `benchmarks/baseline.json`, `benchmarks/summary.txt` (regenerate with
  `python benchmarks/summarize.py`).

## R1.01 measured effect (same conditions A/B)

- Non-due publication: **1.40 ms → 0.015 ms (200k)**, **7.46 ms → 0.015 ms
  (1M serial)** — the removed cost equals ~46–54% of one full explicit step
  (i.e. the redundant force pass), now ~free.
- Due pure-U snapshot: −1.3 ms (200k) / −7.1 ms (1M): force pass skipped for
  displacement-only frames.
- Steady stepping, cold compile, and all IO timings unchanged within noise
  (steady/step 200k serial: 2.687 eager vs 2.783 lazy; spread across repeated
  runs exceeds the difference).
- `force_evaluations` 14 → 12 in-benchmark, matching the R1.01 unit-contract
  counts.

## Honest observations recorded for later batches

- OMP4 ≈ serial on this bandwidth-bound generated model (both ~2.6 ms/step
  @200k, ~15 ms @1M): consistent with the previously reported low threading
  efficiency; this is R2.01/R2.02 territory, not fixed here.
- `reader_scan_query_ms` ≈ `native_write_ms`: the reader still scans all
  frames (known R4 target).
- 1M numbers are single samples (one run each); treat as scale indicators,
  not medians.
