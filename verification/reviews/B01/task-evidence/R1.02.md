# R1.02 — Physical time-layer and read-only output publication contract

## What this task delivers

No runtime-behavior change. The publication contract that R1.01's laziness
relies on is now locked by explicit tests (previously only partially covered
by value checks at the final frame).

## Contract codified in `tests/lifecycle_tests.cpp` (block "R1.02")

All under `lifecycle_contracts`; suite total after this task:
`lifecycle checks=14284 PASS` (was 6154).

1. **Read-only publication**: at every one of the 2001 visited increments
   (before/after each `advance()`), the trajectory signature — displacement,
   velocity, acceleration, external force, contact force, material history
   field, step, time, dt — is bit-identical across two consecutive
   `snapshot()` calls. `StateDB::in_trial()` is false throughout (no history
   commit, no trial state).
2. **Repeatable publication**: `native::pack(snapshot())` equal for two calls
   at the same cursor.
3. **Coherent physical time layer** at all 21 due frames of the forced
   oscillator (analytic solution u(t)=.06(1−cos 20t)):
   - `U` at t[n] (tol 1e-7),
   - `V` reconstructed to full time, =1.2 sin 20t (tol 2e-5),
   - `A` at t[n], =24 cos 20t (tol 1e-4),
   - `S` coherent with `U` at the same frame (stress = 100·u, tol 1e-11),
   - `frame.info.time == state time`.
4. **Across a step boundary with dt change and load release** (dt 0.0001 →
   0.0002 at t=0.1, `*Cload,op=NEW`): published U/V/A at each step-1 output
   frame match the released-oscillator analytic solution
   (u(τ)=u₁cos 20τ+v₁/20 sin 20τ, a=−400u) — tolerances 2e-6 / 3e-5 / 2e-3.
   This verifies the half-step rephasing in `CpuRun::next_step()` leaves a
   publishable, physically-consistent layer after the transition, and that
   velocity lag is dt-new based.
5. **Restart publication equivalence** remains covered byte-for-byte by the
   existing `numerical<T>` split/restart-append checks (frames 8–20 of the
   split file are published by the resumed run and byte-match the continuous
   run); combined with (1) this is "consistent across restart without history
   commit".

## Test-development note (honest debugging record)

The first version of check (4) read `values[9]` out of the **history** `U`
field (region FREE, 1 entity) by taking the last name match — an out-of-range
read on a 3-value vector producing garbage. Fixed by selecting only
non-history fields for the full-model layer checks. This was a test defect,
not a product defect; the product fields were correct (verified by a scratch
debug program comparing published V to the analytic released solution, which
matched to ~5e-9 before the fix).
