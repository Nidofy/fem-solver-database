# R1.01 — Avoid redundant force evaluation on non-output timesteps

## Problem (verified against HEAD aaa74af source)

`ResultPublisher::publish()` (include/sdb/results/results.hpp) called
`cpu.forces(state)` unconditionally before any `OutputScheduler::due()` check,
and `sdb_run` snapshots after **every** increment. Every non-output increment
therefore paid a full element-kernel + assembly pass whose result was never
stored (empty frames were already skipped by `ResultWriter::write`; the waste
was compute only, never disk bytes).

## Change

1. `ResultPublisher::publish()` now selects due requests first and evaluates
   constitutive state only when (a) some request is due and (b) some due
   variable needs force/stress/strain data — i.e. anything except a pure `U`
   frame. Non-due increments and pure-U frames cost no force evaluation.
2. `CpuExplicit::forces()` counts completed evaluations
   (`force_evaluations()`); `CpuRun` forwards it (ADR-0003). One integer
   increment per call; header-only template, no ABI break.
3. `CpuRun::save()` evaluates forces once before serializing so restart files
   keep storing a displacement-consistent force field at ANY stop point, not
   only output-due ones (byte compatibility preserved — see below).

## Test-first evidence

New assertions in `tests/lifecycle_tests.cpp` (all inside `lifecycle_contracts`):

- exposing run against the pre-fix header (fix stashed): test FAILED at
  `no-output publication costs no force evaluations` (eager path cost one
  extra evaluation for a frequency=0 snapshot) — command
  `sdb_lifecycle_tests.exe tests/fixtures/abaqus build-b01/expose-scratch`,
  output ended with that failure message before `lifecycle checks=... PASS`.
- with the fix applied: `lifecycle checks=6154 PASS` (exit 0). The contract
  assertions now hold:
  - full fixture request set (frequency=100, 2000 increments): publication adds
    a force evaluation **only** on the 21 due increments (0, 100, …, 2000);
    total = 2000 steps + 1 initialize + 21 due publications = 2022
    (pre-fix behavior: 4002 — measured by the same assertion failing on the
    eager build at `publication evaluates only due increments`).
  - U-only output (frequency=100): 21 due frames published with **zero**
    force evaluations; total = 2001.
  - U-only trajectory is bit-identical to the full-request run
    (`displacement(3,0)` compared with `==`).

## Byte-level compatibility (old `build/` pre-fix binaries vs new build-b01)

| Artifact | Command delta | Result |
|---|---|---|
| full result, double | `sdb_run --input forced_tet.inp --precision double` | `cmp` IDENTICAL |
| full result, float | `--precision float` | IDENTICAL |
| U-only result | INP variant with only `U` field output | IDENTICAL |
| split flow result | `--stop-after 700 --checkpoint` (due stop) | IDENTICAL |
| restart checkpoint, due stop 700 | as above | IDENTICAL |
| restart checkpoint, **non-due stop 733** | `--stop-after 733 --checkpoint` | IDENTICAL |

The 733 case is the one that motivated the `save()` evaluation: without it the
lazy path would have serialized a force field one evaluation older than the
eager path, changing restart bytes at non-due stop points.

## Scope / non-goals

- No schema, file-format, time-layer or default-path change; single-commit
  revert possible.
- `sdb_run` still calls `storage.last()` and constructs `FrameInfo` every
  increment — the remaining per-increment cost is trivial by design.
